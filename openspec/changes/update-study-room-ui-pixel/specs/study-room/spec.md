## MODIFIED Requirements
### Requirement: 覆盖层展示加入指引
学习室覆盖层 MUST 提供主题化的界面，同时保持实时的加入提示、座位信息与候补数据。

#### Scenario: 像素风皮肤显示加入提示
- **GIVEN** 已选择像素风皮肤
- **WHEN** 覆盖层收到包含 `joinPrompt` 的状态
- **THEN** 加入横幅以像素风样式显示空位数量与主要指令
- **AND** 像素字体在 720p/1080p 分辨率下保持清晰且无抗锯齿模糊
#### Scenario: 左侧主图书馆展示座位图
- **GIVEN** 像素风皮肤提供一张座位图背景图片
- **WHEN** 覆盖层渲染左侧主区域
- **THEN** 背景图以像素对齐方式显示
- **AND** 每个座位或区域预留可点击/高亮的锚点方便后续绑定数据

#### Scenario: 皮肤切换不影响逻辑
- **GIVEN** 存在至少两种主题（像素风与默认主题）
- **WHEN** 配置或 URL 中指定切换主题
- **THEN** 皮肤层加载对应样式与组件
- **AND** 底层数据轮询、事件处理、toast 逻辑保持一致，无状态丢失

### Requirement: 座位时间看板
右侧座位板 MUST 仅展示已入座观众及其学习时长，提供像素风排版以增强数据对比度。

#### Scenario: 坐席列表排序
- **GIVEN** 多名观众已入座
- **WHEN** 覆盖层渲染座位板
- **THEN** 默认按学习时长降序排列，并显示用户名与累计学习时间
- **AND** 列表支持滚动以容纳超过可视范围的观众

#### Scenario: 与主区域状态同步
- **GIVEN** 左侧主区域更新了座位状态（例如某用户离席或候补补位）
- **WHEN** 数据轮询返回最新状态
- **THEN** 右侧座位板在一次渲染周期内同步反映变更，无状态延迟

### Requirement: 管理主题预设
系统 MUST 允许在保持逻辑复用的前提下，为学习室覆盖层注册多个主题皮肤，并通过 `src-library` 目录的主题注册机制完成加载。

#### Scenario: 注册新皮肤
- **GIVEN** 主题接口文档
- **WHEN** 开发者提供新的皮肤实现并注册
- **THEN** 覆盖层可以在无需修改核心逻辑的情况下加载该皮肤
- **AND** 皮肤可以自带资源（样式/图像）并按需懒加载
